# Guide: choose evidence and verification

Start with the claim, not the tool:

1. State exactly what must be proven.
2. Identify the system that owns the target state.
3. Choose an observation independent of the worker's self-report.
4. Bind it to principal, task, target, route, revision, and time.
5. Define freshness and what makes it stale.
6. Record the evidence reference and verification result in the receipt.

Examples: an API acceptance needs an authenticated provider response; a CRM change needs a target read or authoritative event tied to the correct tenant and record; a deployment needs the deployed revision, correct listener/route, and a functional check; a genuine lead needs applicable-site evidence and reconciliation, not only an advertising conversion.
