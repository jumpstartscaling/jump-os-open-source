# LinkedIn launch post

I’m open-sourcing Jump OS: an architectural framework for governed enterprise agentic work.

The hard problem with enterprise AI is not getting a model to call a tool. It is knowing whether the action was authorized, which task owned it, what policy applied, what actually ran, what evidence came out, and how to recover when reality disagrees with the plan.

Jump OS is built around a few simple rules:

- identity, policy, and task authority stay distinct;
- contracts, source intent, runtime observations, and human explanations remain separate truth lanes;
- graphs and embeddings suggest relationships but do not manufacture proof;
- every meaningful execution should produce a durable receipt;
- production mutations should be bounded, verified, and recoverable.

This first release is intentionally an architectural research and community specification project. It does not expose private Jumpstart Scaling infrastructure or pretend that a diagram is a production implementation.

I’m especially interested in feedback from people working on agent governance, MCP/A2A boundaries, policy-as-code, auditability, rollback, and enterprise compliance. What would you require before trusting an agent to change business state?
